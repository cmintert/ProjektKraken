Memory Management Strategy
---------------------------
┌────────────────────────────────────────────────────────────┐
│  In-Memory Command Stack                                   │
│  ┌──────────────────────────────────────────────────────┐  │
│  │  Max Size: 100 commands                              │  │
│  │  ┌────────────────────────────────────────────────┐  │  │
│  │  │ [99] Most Recent  ◄─── User sees these in UI  │  │  │
│  │  │ [98] ...                                       │  │  │
│  │  │ [97] ...                                       │  │  │
│  │  │ ...                                            │  │  │
│  │  │ [20] ...                                       │  │  │
│  │  │ ▼▼▼ Archive Threshold (80 commands) ▼▼▼       │  │  │
│  │  │ [19] ...                                       │  │  │
│  │  │ ...                                            │  │  │
│  │  │ [0]  Oldest       ◄─── Archive to DB when >100│  │  │
│  │  └────────────────────────────────────────────────┘  │  │
│  └──────────────────────────────────────────────────────┘  │
│                                                             │
│  When stack reaches 100:                                   │
│    1. Save commands [0-49] to database                     │
│    2. Keep commands [50-99] in memory                      │
│    3. Continue with 50 commands in stack                   │
└─────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────┐
│  Database Archive (Long-term Storage)                      │
│  ┌──────────────────────────────────────────────────────┐  │
│  │  All historical commands (unlimited)                 │  │
│  │  ┌────────────────────────────────────────────────┐  │  │
│  │  │ Session 1: 500 commands (archived)            │  │  │
│  │  │ Session 2: 300 commands (archived)            │  │  │
│  │  │ Session 3: 150 commands (recent)              │  │  │
│  │  │ Session 4: 50 commands (in-memory)            │  │  │
│  │  └────────────────────────────────────────────────┘  │  │
│  └──────────────────────────────────────────────────────┘  │
│                                                             │
│  On world open:                                            │
│    Load last 100 commands into undo_stack                  │
│                                                             │
│  For "View History" feature (Phase 4):                     │
│    Query database for all commands, paginate               │
└─────────────────────────────────────────────────────────────┘


NOT RECOMMENDED: Full Event Sourcing
-------------------------------------
┌─────────────────────────────────────────────────────────────┐
│  ❌ Event Sourcing Approach (Too Complex)                  │
│  ┌──────────────────────────────────────────────────────┐  │
│  │  Every data change stored as event:                  │  │
│  │                                                       │  │
│  │  Traditional:                                         │  │
│  │    UPDATE events SET name = 'New' WHERE id = '123'   │  │
│  │                                                       │  │
│  │  Event Sourcing:                                      │  │
│  │    INSERT INTO event_log VALUES (                    │  │
│  │      aggregate_id='123',                             │  │
│  │      event_type='name_changed',                      │  │
│  │      patch='{"op":"replace","path":"/name",...}'     │  │
│  │    )                                                 │  │
│  │                                                       │  │
│  │  Current state = replay ALL events in order          │  │
│  └──────────────────────────────────────────────────────┘  │
│                                                             │
│  Why NOT recommended for ProjektKraken:                    │
│  ❌ Complex: Need replay mechanism, snapshots             │
│  ❌ Slow: Reconstructing state requires replaying events  │
│  ❌ Overkill: Desktop app doesn't need this               │
│  ❌ Maintenance: High complexity burden                   │
│                                                             │
│  When Event Sourcing IS good:                              │
│  ✅ Distributed systems (microservices)                   │
│  ✅ Audit requirements (compliance)                       │
│  ✅ Real-time collaboration (Google Docs)                 │
│  ❌ Single-user desktop app (ProjektKraken)               │
└─────────────────────────────────────────────────────────────┘
